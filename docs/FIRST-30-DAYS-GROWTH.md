# YouNew — first 30 days after authorised launch

Constraint: €0 tooling budget. Start this plan only after production authorisation and successful live smoke checks. Do not send unsolicited outreach merely because a public address or contact form exists.

## Outcomes to measure

The first month should establish evidence, not forecasts:

- non-bot organic landing sessions by EN/NL landing page;
- Search Console impressions, clicks, queries and indexed canonical URLs;
- city-guide engagement and onward clicks to official sources;
- organisation/profile views only for factually verified profiles;
- `lead_start`, validation failure, accepted application and verified registration;
- consent rate and analytics event rejection rate;
- number of partner identities reviewed, lawful-channel decisions, authorised contacts, replies and registrations;
- freshness coverage and median days since field-level review.

No revenue claim should be made from interest checkboxes, drafts or unverified leads.

## Days 0–2: launch safety

1. Run the production checklist from `PRODUCTION-GO-NO-GO.md`.
2. Confirm the seven-record fail-closed catalogue and absence of the 170 excluded records.
3. Run one synthetic EN and NL application end to end, confirm persistence and purge the fixtures.
4. Confirm consent-gated analytics: no event before choice, no email/phone/free text in payloads.
5. Submit the canonical sitemap in Search Console and record submission, not indexing, as the result.
6. Capture baseline uptime, 4xx/5xx, Edge failure and application conversion numbers.

## Days 3–7: first discoverability loop

1. Inspect Search Console URL status for the homepage, NL homepage and five city guides.
2. Improve titles or introductions only where observed queries reveal a mismatch; preserve verified claims.
3. Add internal links from the five city guides to relevant non-empty categories and official-source actions.
4. Publish one NL and one EN owned-channel post per guide using only verified guide facts.
5. Ask existing personal/professional networks to review the public product, not to simulate clicks or reviews.
6. Record crawl/index status and do not create duplicate city pages to chase keywords.

## Days 8–14: lawful partner preparation

1. Manually review the 14 candidates whose official channels may permit a relevant first approach.
2. For each candidate, record the precise channel purpose, terms, legal basis/consent evidence, reviewer and decision date.
3. Keep the other 16 as inbound/research only unless new evidence changes the classification.
4. Use the prepared Dutch free-listing draft only after an approved decision; personalise it with verified company facts and offer €0 profile review.
5. Send no message in bulk. The owner separately approves every first-contact batch and sending identity.
6. Track `sent`, `replied`, `interested` and `registered` only from observable evidence.

## Days 15–21: conversion learning

1. Review form starts, validation errors and completed applications by locale.
2. Interview willing applicants about which verified profile information matters; do not imply unavailable Premium features.
3. Compare restaurant, shop and service-company responses as small samples, not market-wide estimates.
4. Shorten confusing form copy only when field errors or interviews show friction.
5. Review application SLA, duplicate rate and spam rate; fix operational bottlenecks before increasing traffic.

## Days 22–30: proof and next decision

1. Reconcile Search Console clicks with privacy-safe analytics landing sessions.
2. Report verified registrations, not submitted or drafted applications, as acquired businesses.
3. Report the exact numerator and denominator for visitor-to-lead and lead-to-registration conversion.
4. Refresh only records that received field-level source confirmation; retain exclusions for all others.
5. Decide whether the next month should prioritise source verification, query coverage or partner onboarding based on observed bottlenecks.

## Month-one decision thresholds

These are operating triggers, not revenue forecasts:

- If any stale record appears publicly: remove it immediately and treat as a release incident.
- If an application fails to persist: stop acquisition calls to action until corrected.
- If privacy review finds contact data in analytics: disable the affected event and purge it under the retention procedure.
- If indexed pages remain near zero after two weeks: investigate robots, sitemap processing, canonical selection and render accessibility before creating more content.
- If form starts occur but completions do not: inspect validation and comprehension before adding fields or paid features.
- If lawful outreach yields no replies: test the offer and channel with a smaller reviewed batch; do not scale volume.

## Evidence that supports future valuation

Maintain a monthly, reproducible table for verified catalogue coverage, indexed pages, organic non-bot sessions, official-source clicks, accepted applications, verified business registrations, activation time, 30-day retention, consent compliance, freshness SLA, incident count and cost to operate. A buyer can diligence these measures; feature counts and unsupported forecasts cannot substitute for them.
