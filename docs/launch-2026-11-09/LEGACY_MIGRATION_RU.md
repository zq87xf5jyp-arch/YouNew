# Сохранный перенос старого Admin

Статус: локальная репетиция завершена; реальный импорт в Hostinger и production ещё не выполнены. Исходные Supabase database/Storage экспортированы без активации проекта, сохранены локально и на Hostinger. Приватные данные, пароли, токены и SQL dump не входят в Git.

## Что сохраняется

`prepare-legacy.py` проверяет SHA-256 обоих экспортов, читает PostgreSQL COPY как данные и никогда не исполняет SQL. В приватный bundle входят все 90 таблиц / 1396 строк, исходные COPY-байты, имена столбцов, JSON-проекция и единственный файл Storage (369 байт). ZIP не распаковывается в файловую систему; неожиданные, отсутствующие или повторяющиеся записи отклоняются.

`import-legacy.mjs` требует точный bundle checksum и пустую целевую базу. В одной транзакции создаются архив, рабочее пространство, четыре профиля, три бизнес-заявки и файл. Каждый архивный ряд и файл проверяется побайтно до commit. Повторный импорт сверяет архив и ничего не перезаписывает. Ошибка оставляет целевую базу без частичного импорта.

- Сохранены ID, email, имена, bcrypt cost-10, роли и признаки одобрения аккаунтов. Пароли не сбрасываются; прежние токены/сессии не активируются. MFA/SSO/неподдерживаемые состояния требуют отдельного review и блокируют автоматический импорт.
- Исходная модель имела глобальные роли, без workspace/tenant. Для этих данных выделен один workspace `b8813c64-a7b8-49aa-a10b-89eea40c9769`; роли и одобрения не расширяются.
- Три исходные заявки со статусом `test` сохранены полностью. По ранее проверенному правилу pipeline их рабочий статус — `archived`, исходный статус остаётся в `legacy_status`. Они не удаляются и не считаются продажами.
- Временные метки перенесены с исходной микросекундной точностью. Все 33 исходных поля заявок доступны в неизменяемом архиве независимо от рабочей проекции.
- История доступна только владельцу; список таблиц явно ограничен бизнес-данными и контентом. Auth/vault/system-таблицы не выдаются в интерфейс. Скачивание сохранённого файла требует владельца того же workspace, проверяет длину/SHA и отдаёт `private, no-store` как attachment.
- 71 новый редакторский материал доступен как приватное превью EN/NL. Сервер блокирует создание/изменение/одобрение каталога в production mode до разрешения конкретной партии. Синтетический QA-каталог в production не импортируется.

## Проверено локально

Изолированная MariaDB 13.0.2 использует отдельный datadir и Unix socket, TCP отключён. Никакие прежние локальные БД не изменялись.

1. Полный импорт и повторный вызов — PASS.
2. Dump в новый приватный файл и restore в другую пустую базу — PASS: количество строк и `CHECKSUM TABLE EXTENDED` совпали для всех 16 таблиц; исходный файл проверен повторно.
3. Искусственный отказ после записи архива, при создании профилей — PASS: транзакция откатила все архивные и активные записи, включая файл.
4. 42 HTTP-проверки синтетического Admin в production mode — PASS: owner/viewer/другой workspace, история, исходный статус, приватный файл, no-store, logout, запрет публикации, журнал и отсутствие неподдерживаемых маршрутов.
5. Safari: вход, раскрытие истории, фильтр Hortus, переключение EN/NL и карточка черновика работают. Точный viewport 390 px и browser console для нового Admin ещё не проверены.
6. PHP outbox: BUSINESS-выборка проходит мимо 21 более старой записи feedback; feedback сохраняется. Локальные проверки форм — `LEGACY_MIGRATION_LOCAL_EVIDENCE.json`.

Это не заменяет проверку MariaDB 11.8.9 Hostinger, реального входа владельца и серверного cron после миграции.

## Откат

До переключения production старый сайт и новая база независимы. Ошибка импортера вызывает transaction rollback; частичный DDL не маскируется и не исправляется удалением таблиц. Новую неудачную среду сохранить для разбора.

После начала приёма новых заявок откатывается только код/маршрутизация. Нельзя возвращать старый DB dump поверх живых данных или включать старый Supabase backend вместо новой очереди. При отказе доставки остановить только новый worker, сохранить SQLite outbox и acknowledgements; публичная форма продолжает долговечное локальное сохранение. Старый архив кода и env должны быть проверены до переключения. Финальная команда production rollback и её серверная репетиция пока не выполнены.
