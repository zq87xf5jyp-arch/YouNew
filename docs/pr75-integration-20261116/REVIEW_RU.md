## Проверяемость и ограничения

Все 177 ссылок источников/лицензий открыты 16 ноября: 174 автоматических HTTP 200; OBA и две страницы Trompenburg — HTTP 200 в обычном видимом Chrome после 429/сетевых ошибок автоматического клиента. Обход блокировок не применялся. Исходные даты проверки фактов не перезаписаны датой этой проверки доступности.

У Nieuwe Kerk числовые часы по-прежнему исключены: официальные страницы противоречат друг другу без ясного периода применимости. Официальные ссылки и объяснение сохранены.

Архитектура использует прежний governed pipeline и компоненты YouNew. Добавлены только преобразование точной selection, контроль отдельных одобрений, явное архивное размещение и отображение подборок. ID и совместимость схемы сохранены; новая база и новый сайт не создаются.

Полевая выборка Core Web Vitals, настоящий Safari/iPhone, App Store Connect и синхронизация web/iOS не подтверждены. Наличие готового кандидата не меняет статус всей платформы на «полностью готова».

## Выпуск после одобрений

1. Записать дословные точные решения владельца; активировать только новый интеграционный манифест, не исходные замороженные партии.
2. Собрать обычный production-кандидат штатной сборкой. Проверить 106 сущностей, отсутствие private marker, исходные gates и корректные текущие данные `/status/`.
3. Повторить полный predeploy и CI на точном коммите; проверить именно обычный кандидат на защищённом Hostinger QA.
4. Перепроверить изменяемые факты перед выпуском; если содержание меняется, получить новое одобрение изменённых хешей.
5. Привязать SHA-256 финального архива, резервную копию и тест отката к отдельному разрешению владельца на deploy.
6. Выпустить прежним механизмом Hostinger, сравнить HTTP-ответы/файлы с кандидатом, проверить действия и мобильные экраны. При расхождении вернуть предыдущий статический каталог, сохраняя новые пользовательские данные.
